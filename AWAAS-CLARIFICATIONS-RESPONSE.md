**18. G5 opening fusion algorithm.** PROVEN (`server/opening_fusion.py`, `augment_openings()`, called from `_ml_scene_from_png` in main.py). **25. pdf_vector.py end-to-end.** PROVEN. (1) Open PDF with PyMuPDF; read vector drawings per OCG layer when layers exist (wall/window/column layers), else geometry-mode over all linework; junk filtering. (2) Scale: dominant column box = 12 in heuristic, or dimension-text parsing (`ft-in` strings), or `width_ft` override; envelope snapping — if verified "overall dimension" text exists, the outer envelope is snapped to it (`_overall_dims`/`_snap_envelope`). (3) Multi-wing: cluster geometry into wings; score by (enclosed room pockets, doors, area) — rooms FIRST so a door-schedule block can't win; user can force `wing=N`. (4) Walls → `walls_poly` polygons (angled walls supported). (5) Rooms = enclosed pockets in the wall mask; if 0 rooms → G1 rescue: morphological close on a rooms-only mask (`_footprint_free_mask`, seal ≤ `DRISHTI_ROOM_SEAL_FT`). (6) Openings: window layer boxes; doors from arcs/tags (D1/D2… via tag_openings) then footprint validation (span ≤6 ft, thickness ≤1.6 ft, else demoted to unsnapped); PPF>0 guard. (7) Room labels from live PDF text; if text is outlined → G2 OCR (when tesseract present). (8) G3 door-median scale check (`_door_median_ft` → flag or `_rescale_scene_ft`). Known limits: dead/outlined text sheets lose labels without OCR; wall-layer-missing sheets depend on G1; window extraction needs a window layer or W-tags; curved walls approximated; door swing arcs sometimes absent → unsnapped doors.

**26. G3 scale correction.** PROVEN. Median ft width of detected doors is computed; a sane Indian door is ~2.5–4 ft. If the scale came from an UNTRUSTED source (not in `TRUSTED_SCALES = {dimension_text, cad_units, room_dim_text}`) and the door median is far off nominal (~3 ft), then: default (`DRISHTI_AUTOSCALE=0`) → FLAG ONLY (`scale_door_mismatch` fail in Plan Doctor, efficiency → needs_review); with `DRISHTI_AUTOSCALE=1` → `_rescale_scene_ft` multiplies every ft field (walls, rooms, openings, areas, wall thicknesses, pt_per_ft) by nominal/median — never z-heights. It declines to rescale when the scale source is trusted or doors are too few/odd. Kept OFF by default deliberately: a RERA product must not silently rescale.

**27. G1 healing.** PROVEN. Trigger: ONLY when normal room detection yields 0 rooms (never otherwise — clean plans untouched, corpus-gated). **29. Area maths (post-fix).** PROVEN (`area_statement.py`). Carpet = Σ room polygon areas. Wall material = Σ (wall outer − holes). Gross outer = area of the outermost footprint. Built-up = gross_outer when the outer polygon is genuinely gross (≥ carpet); else carpet + wall_material (thin-strip-shaped scenes); fallback envelope W×D; final floor `built_up = max(built_up, carpet)`. Super built-up = `max(carpet × loading_factor, built_up)` — loading applies to CARPET (Indian market convention; the old built_up×loading double-counted walls). Default loading_factor = **1.30**, applied in `compute_area_statement` (query-param overridable, and via G7). Efficiency = 100 × carpet / super. Displayed efficiency < 0.05 → "needs_review", never a silent 0.

**30. Vastu.** PROVEN (`vastu.py`). Each room's centroid is placed on a 3×3 grid over the plan envelope (center zone = 33% band, `center_frac=0.33`), sectors N/NE/E/SE/S/SW/W/NW + center (Brahmasthan); `north_deg` rotates the compass (0 = top of sheet, user-settable in the UI). Verdict table `_RULES` maps room type → good/bad zones with advice strings (e.g. kitchen SE good, NE bad); neutral types (parking, balcony, lobby, untyped) are skipped. Source of the table: standard Vastu conventions compiled by me during the 21 Jul build — NOT vetted by a Vastu consultant (flag if the product markets this seriously). Output: per-room verdicts + an aggregate score (null when no typed rooms).
